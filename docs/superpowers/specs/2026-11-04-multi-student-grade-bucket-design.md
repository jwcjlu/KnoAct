# 多学生管理 + 年级/学年桶设计

> 日期：2026-11-04
> 状态：已与用户逐节确认

## 背景与目标

KnoAct 目前是「单孩子、无年级」模型：`User` 只有 `name` + `role`，数据全部挂在
`user_id` 上，没有年级维度，也没有家长-孩子归属关系。家长端「孩子列表」只是
`GET /api/users?role=child` 拉全局所有 child。

需求：

1. **多学生管理**：一个家长名下挂多个孩子；家长端切换孩子，孩子端各自登录。
2. **年级/学年**：孩子有当前年级，随自然学年（9 月）自动升级，家长也可手动升/改。
3. **回看历史**：升年级后仍能回看低年级（如三年级）的错题本、练习题、掌握度、积分、目标。
4. **学习配置按孩子**：学习规则（难度/题数/听写量等）按孩子可单独配置，未配则用全局默认。
5. **教材分版本**：不同地区教材版本不同，同版本同年级的孩子共享教材内容。

## 核心决策

| 决策 | 结论 |
|------|------|
| 家长/孩子关系 | 两者都要：家长端切换孩子 + 孩子端各自登录 |
| 年级推进 | 自然学年（9 月）自动升级 + 家长手动升/改 |
| 年级存法 | 整数编号（1~6 = 一~六年级），升级 `+1`，前端映射中文 |
| 历史数据 | **真正分桶隔离**：升年级封存旧桶、开新桶，积分清零重来 |
| 桶建模 | 引入 `SchoolYearBucket` 主表，数据挂 `bucket_id` 外键 |
| 教材 | 教材库共享，按「学科+年级+版本」去重（同版本同年级共享一份） |
| 题目 | **全部按孩子生成**（练习题、边读边问），挂在学年桶下 |
| 学习配置 | 跨学年沿用不分桶；模型/语音按孩子覆盖放二期 |

---

## 第 1 节：数据模型

### 1.1 孩子档案（`User` 表扩展）

| 字段 | 类型 | 说明 |
|------|------|------|
| `grade` | Integer | 当前年级，1~6（一年级~六年级），可扩展 0=学前、7=初一 |
| `edition` | String | 当前教材版本（人教版/苏教版/北师大版…），可空 |
| `parent_id` | FK→users.id | 归属家长，可空（家长本身为空） |

登录逻辑保持「按名字查、无则建」的简化方式，但家长创建孩子时挂 `parent_id` +
设 `grade`/`edition`。

### 1.2 教材库（共享层）

- `PdfDocument` 加 `edition`（版本）、`grade`（年级）字段。
- `Lesson` / `WordBank` / `KnowledgePoint` / `Text` 随 `PdfDocument` 走，本身不加字段
  （它们已通过 `lesson_id`/`document_id` 挂到教材链上）。
- 教材库按「学科 + 年级 + 版本」去重：同版本同年级的孩子复用同一份教材及其拆课结果。

### 1.3 学年桶（`SchoolYearBucket` 新表）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | PK | |
| `user_id` | FK→users.id | 属于哪个孩子 |
| `grade` | Integer | 该桶对应的年级（如 3） |
| `school_year` | String | 学年（如 `2025-2026`） |
| `started_at` / `ended_at` | DateTime | 学年起止（默认 9-1 ~ 8-31） |
| `status` | String | `active` / `archived` |

每个孩子同一时间最多一个 `active` 桶。升年级 = 把当前桶置 `archived`，新建一个
`grade+1`、新学年的 `active` 桶。

### 1.4 学习痕迹挂桶（个人层）

以下表都加 `bucket_id`（FK→SchoolYearBucket）：

- `Mistake`（错题本）
- `Task`（每日任务）
- `Question`（练习题，含每日阅读/听力题）— 改为按孩子生成，加 `user_id` + `bucket_id`
- `Quiz`（边读边问）
- `WordMastery` / `KnowledgeMastery`（掌握度）
- `Point`（积分）
- `Goal`（目标）

每个孩子的这些记录，只归到**当时 active 的桶**下。升年级封存旧桶后，旧数据留在旧桶，
新数据写入新桶。

### 边界

- 教材库只共享**纯内容**（PDF/课文/生词/知识点）。
- **题目和所有练习都按孩子生成、挂在学年桶下**。
- 积分/掌握度「各学年各算各的」：升年级后新桶从 0 开始，旧桶封存。

## 第 2 节：年级升级流程

### 触发方式

- **自动升级**：系统在「学年切换点」（9 月 1 日）自动把孩子的 `grade` +1，并封存旧桶、
  开新桶。挂在 main.py 现有每日 03:00 调度器上，每天检查。
- **手动升级**：家长在家长端给孩子点「升年级」，立即 `grade+1`、封存旧桶开新桶
  （应对跳级/留级/转学，或家长想提前升）。
- **手动改年级**：家长可直接改孩子的年级（非 +1），系统按目标年级建新桶、封存当前桶。

### 升级动作（幂等，核心逻辑）

升年级执行以下原子操作：

1. 找到该孩子当前 `active` 桶，置为 `archived`，记 `ended_at`；
2. 新建一个桶：`grade = 旧grade + 1`，`school_year = 新学年`，`status = active`；
3. 更新 `User.grade = 旧grade + 1`；
4. 若孩子档案有 `edition`，新桶/新年级沿用（同版本教材到四年级也用它，除非家长改版本）。

关键约束：**升级必须幂等**——同一天多次触发（自动+手动撞上）不能重复升级、不能开出两个
active 桶。用「检查当前 grade 是否已等于目标」来保证。

### 学年计算

- `school_year` 格式 `YYYY-YYYY`（如 `2025-2026`），9 月 1 日 ~ 次年 8 月 31 日。
- 自动升级时：若当前日期 ≥ 9 月 1 日，目标学年 = 当前年 ~ 次年；否则 = 去年 ~ 今年。
- 家长手动升年级时：`school_year` 用「触发日期的当前学年」推算（家长 3 月提前升四年级，
  学年仍是 `2025-2026`，只是年级从 3→4）。

### 边界情况

- **留级**：家长手动改 `grade` 为同级或更小，系统封存当前桶、按目标年级建新桶（不 +1）。
- **跳级**：家长改 grade 为 +2 或更大，同理建对应年级桶。
- **第一个桶**：孩子建档时（家长创建孩子）即建第一个 `active` 桶（`grade=建档年级`，
  `school_year=建档时的学年`）。没有桶的孩子视为「数据异常」，首次有学习行为时兜底建桶。

## 第 3 节：回看 / 切换

### 孩子端（Flutter 学生端）

孩子默认看**当前 active 桶**（本学年本年级）的数据：错题本、练习题、掌握度、积分、目标。

需要「**学年切换**」入口，让孩子（或家长帮孩子）切到历史学年回看：

- 在错题本、练习题等页面的顶部加「学年」下拉/胶囊，选项来自该孩子的所有桶
  （按年级降序，如「四年级（2026-2027）」「三年级（2025-2026）」）。
- 切换后，当前页面的数据全部按选中的桶过滤（错题本只显示三年级桶的错题、积分只显示
  三年级桶的积分）。
- 默认选中「当前 active 桶」，切到历史桶时页面标注「历史学年，只读」。

### 家长端（parent-web 原生 JS）

1. **孩子列表改为「我名下的孩子」**：`GET /api/users?role=child&parent_id=<家长>`。
2. **每个孩子可进入「学年视图」**：看该孩子某个学年的错题本、练习题、掌握度、积分、目标。
3. **家长可操作**：建孩子（设年级/版本/归属）、升年级、改年级、改版本。

### API 层

所有「学习痕迹」相关的查询端点，增加可选参数 `bucket_id`（或 `school_year`），默认取当前
active 桶：

- `GET /api/mistakes?bucket_id=…`
- `GET /api/tasks?bucket_id=…`
- `GET /api/questions?bucket_id=…`
- `GET /api/mastery?bucket_id=…`
- `GET /api/points?bucket_id=…`
- `GET /api/goals?bucket_id=…`

前端切换学年时带上对应 `bucket_id`。后端提供 `GET /api/buckets?user_id=…` 列出孩子所有桶，
供前端渲染下拉。

### 只读约束

历史（非 active）桶：**只读**。对历史桶的写操作（新增错题、提交任务、答题、积分变动）
一律拒绝。当前 active 桶才允许写。

### 切换粒度

按「桶（学年×年级）」切，而非只按年级切——这样「三年级留级了两年」也能分清两段。

## 第 4 节：学习配置（按孩子，共享默认 + 单独覆盖）

### 配置分类与现状映射

| 配置类别 | 现状 | 归属 |
|---------|------|------|
| AI/模型/TTS | `ModelConfig` + 三表（`resolve()` 三级降级） | 系统级，孩子可覆盖（二期） |
| 学习规则（难度、每日题数、听写词量、复习间隔、积分规则） | 散在 `ModelConfig` 键值（`difficulty_语文`、`task_dictation_count_语文`…）+ 代码常量 | 系统级默认，孩子可覆盖（一期） |
| 教材版本 | （新增） | 孩子级（`User.edition`） |

### 建模：一张「孩子配置覆盖」表

新增 `ChildConfig`（键值覆盖表）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `user_id` | FK→users.id | 哪个孩子 |
| `key` | String | 与 `ModelConfig.key` 同构的配置键 |
| `value` | LongText | 覆盖值 |

（配置跨学年沿用、不分桶。）

### 读取逻辑（三级降级，孩子优先）

```
读配置(child_id, key):
    1. ChildConfig 有 (child_id, key) → 用孩子自己的
    2. ModelConfig 有 key（全局默认）→ 用全局
    3. 代码默认值 → 用默认
```

即把现有的 `_cfg_str(db, key, default)` / `_default_count(db, key, default)` 加一个
`child_id` 参数，内部先查 `ChildConfig`。改动集中在配置读取函数这一层，业务代码几乎不用动。

### 模型/语音配置（二期）

- 现有 `resolve(db, role)` 是全局的。要「孩子可覆盖模型/语音」，可在 `RoleBinding`/
  `ModelProfile` 增加「孩子维度」。
- **放二期**：一期只做「学习规则按孩子覆盖 + 教材版本按孩子」。

## 第 5 节：数据迁移与兼容

### 存量数据迁移

现有数据库已有 child 用户和 `Mistake`/`Task`/`Point`/`Goal`/`WordMastery`/
`KnowledgeMastery`/`Question`/`Quiz` 数据，但没有年级、没有桶。

迁移策略：**给存量孩子补「默认桶」，把历史数据归入**。

1. **补年级**：存量 `child` 用户的 `grade` 缺省设为 3（三年级），`edition` 留空由家长补。
2. **建默认桶**：为每个存量孩子建一个 `active` 桶，`grade = 该孩子 grade`，
   `school_year = 当前学年`（2025-2026）。
3. **回填 bucket_id**：把存量 `Mistake`/`Task`/`Point`/`Goal`/`WordMastery`/
   `KnowledgeMastery`/`Quiz` 按 `user_id` 归到刚建的默认桶。

### 存量全局 `Question` 处理

现状 `Question` 是全局每日生成的（无 `user_id`）。改成「按孩子生成」后：

- **丢弃存量全局题**（重生成成本低，每日都会生成新的）。
- **新逻辑**：每日任务调度器改为**遍历每个 active 桶的孩子**，各自生成专属题
  （挂 `user_id` + `bucket_id`）。

### 迁移脚本

幂等迁移脚本（SQLAlchemy，跑一次）：

1. 给存量 child 补 `grade=3`（默认）、建默认 active 桶；
2. 回填各表 `bucket_id`；
3. 丢弃存量全局 `Question`；
4. 新增表 `SchoolYearBucket`、`ChildConfig`，以及各表的 `bucket_id` 列
   （`ALTER TABLE` 或建表时 `nullable` + 回填）。

### 兼容性

- 现有 API 端点默认取「当前 active 桶」数据，**不传 bucket_id 时行为不变**（老前端照常用）。
- 老前端（`frontend/`、`parent-web/`）不受影响；Flutter 学生端和 parent-web 再逐步加
  「切学年」UI。

---

## 遗留 / 二期

- 模型/语音配置按孩子覆盖（`resolve()` 加孩子维度）。
- 教材库去重的「版本字典表」如需扩展版本列表，再评估是否引入 `TextbookEdition` 字典表。

## 测试要点

- 升年级幂等（同日多次触发只升一次、只一个 active 桶）。
- 历史桶只读（写操作被拒）。
- 桶切换过滤正确（切三年级桶只看到三年级数据）。
- 配置三级降级（孩子覆盖 > 全局 > 默认）。
- 教材共享去重（同版本同年级孩子复用同一份教材）。
- 每日任务按孩子生成（每个 active 桶的孩子各自生成）。
