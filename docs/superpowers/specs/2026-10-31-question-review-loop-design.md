# 题目闭环 + 两端信息架构 设计

日期：2026-10-31
状态：已确认，待实现
范围：统一题目模型 + 家长端题目审核台 + 孩子端首页重设计（两端对齐的「今日学习闭环」）

## 背景与目标

当前「题目」散落、两端混乱，核心痛点：

1. **题目散落**：阅读理解题在 `Question` 表，听写词/基础知识问答/听力题在 `Task.content`（JSON，格式各异），数学题在 `Question` 表但走独立接口。没有统一的题目模型和审核机制。
2. **家长端乱**：9 个平铺 tab，「知识点」「题目」与「教材」功能重叠，大量假按钮（编辑/规则点了没反应），题目审核和任务审核重叠。
3. **孩子端乱**：孩子进来不知道今天有哪些任务、哪些没完成——任务卡片混在一起、没有进度总览、空态文案误导。

目标：把「题目从生成到孩子完成」的完整闭环理顺，两端对齐。

## 核心闭环

```
每日出题（按学科/课程）
  → 家长审核（题目审核台：按学科/课程审题，逐题/逐课/逐学科批量）
    → 审核通过 → 题目发布
      → 孩子端首页（古诗勉励 + 今日进度 + 学科 tab 任务）
        → 孩子作答 → 判分 → 掌握度 → 下次出题（遗忘曲线）
```

## 第一部分：统一题目模型（只覆盖「生成类」题目）

### 关键区分：两类每日内容

每日任务分两类，审核要求不同：

| 类型 | 任务 | 内容来源 | 需要审核？ |
|------|------|---------|-----------|
| **听写类** | 生词听写（语文）/ 单词拼写（英语） | 从 `WordBank` 取教材生词（教材已审核） | ❌ 不需要，直接发布 |
| **生成类** | 听力 / 基础知识 / 阅读理解 / 数学 | AI 生成的对话/题目 | ✅ 需要家长审核 |

**`Question` 表只存「生成类」题目**（需要审核的那部分）。听写词/单词继续从 `WordBank` 取，不进 `Question` 表、不审核、孩子端直接显示。

### `Question` 表扩展

现有字段：`id / lesson_id / qtype / question / answer / created_at`

新增字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `subject` | String(16) | 学科：语文/英语/数学（显式存） |
| `date` | Date | 题目归属日期（每日生成的题标当天，历史累积） |
| `status` | String(16) | 审核状态：`pending` / `published` / `rejected`（默认 pending） |
| `extra` | TextCls | 附加数据 JSON（基础知识的关键词、听力的对话等） |
| `task_type` | String(16) | 关联任务类型：knowledge/listening/reading/math |

### `qtype` 取值（仅生成类）

`knowledge | listening | reading | math`（不含 dictation——听写词不落 Question 表）

### 每日生成（累积式，方案 A）

- 每日任务生成（`task_gen`）时，把「生成类」任务的题目**统一落 `Question` 表**（带当天 `date`、`status=pending`、`subject`、`qtype`）
- 「听写类」任务（dictation）不落 Question，继续从 WordBank 取，孩子端直接展示
- 历史题目累积（不覆盖），审核台按 `date=今天 AND status=pending` 过滤

## 第二部分：家长端题目审核台

取代现有「题目」tab。

### 页面结构

按**学科 → 课程**两层组织：

```
题目审核台
├─ 语文
│   ├─ 第1课 桂花雨  [3 待审]  [通过本课]
│   │   ├─ 题1：...  ✓通过 / ✗驳回
│   │   └─ ...
│   └─ 第2课 落花生  ...
├─ 英语
│   └─ Unit 1  ...
└─ 数学
    └─ 第一单元  ...
```

顶部：「出题（按学科/课程）」入口 + 「全部通过」。

### 审核粒度

- 逐题（每题 通过/驳回）
- 逐课（通过本课全部）
- 逐学科（通过某学科全部）

### 状态机

`pending（待审核）→ published（已通过，孩子可见）/ rejected（驳回，回到出题/修改）`

与现有任务 `content_status: pending_review → published` 语义对齐。

## 第三部分：孩子端首页重设计

### 结构（自上而下）

1. **古诗勉励区**（全局固定）：竹/兰/梅/菊四君子，每天轮换一首勉励诗 + 对应水墨配色背景
   - 竹：郑板桥《竹石》（青绿）
   - 兰：幽兰诗（幽青）
   - 梅：王安石《梅花》（红梅）
   - 菊：元稹《菊花》（金黄）
2. **今日总进度**（全局固定）：大数字「N/M」+ 进度条 + 「还差 X 项」提示
3. **学科 tab 切换**：语文/英语/数学，tab 上带「待完成数」角标，某科全完成变「✓」
4. **当前学科任务区**：待完成高亮在前、已完成置灰在后

### 与审核联动

孩子端首页的「待完成」任务 = **审核通过的生成类题目**（`Question.status=published`）+ **直接发布的听写类词条**（dictation，无需审核）。

- 家长审核通过 → 生成类题目 `status=published` → 孩子端对应学科 tab 出现
- 听写词/单词 → 生成即发布 → 孩子端对应学科 tab 直接出现

## 第四部分：家长端信息架构重组（9 → 7）

方案 A（温和合并）：

| 现状（9） | 目标（7） | 变化 |
|-----------|-----------|------|
| 教材 | 教材管理 | 保留 |
| 知识点 | （并入教材详情） | 移除独立 tab |
| 题目 | 题目审核台 | 升级为核心 |
| 任务 | 任务管理 | 保留（与审核台打通） |

| 学习配置 | 学习配置 | 保留 |

侧边栏分组：内容管理（教材/题目审核台/任务管理）、学习规划（目标/报告/规则）、系统（学习配置/模型设置）。

## 数据流

```
task_gen 每日生成
  ├─ 生成类（听力/基础/阅读/数学）→ Question 表（status=pending, date=今天）
  │     → 家长端题目审核台（按学科/课程审）
  │       → 审核通过 → status=published
  │         → 孩子端首页（published 题目）
  └─ 听写类（生词/单词）→ 直接发布（不审核）
        → 孩子端首页（直接显示）

孩子端首页 = published 生成类题目 + 直接发布的听写词条
  → 孩子作答 → 判分 → record_attempt 落掌握度 → next_review_at 更新
```

## 接口

```
# 题目审核台
GET  /api/questions/review?date&subject   → 待审核题目（按学科/课程分组）
POST /api/questions/{id}/approve          → 单题通过
POST /api/questions/{id}/reject           → 单题驳回
POST /api/questions/approve-by-lesson     → 按课批量通过
POST /api/questions/approve-by-subject    → 按学科批量通过
POST /api/questions/generate              → 出题（按学科/课程）

# 孩子端首页
GET  /api/home/tasks?user_id&subject&date → 当前学科当天 published 题目（含完成状态）
```
