# 手写听写（线上听 + 线下写 + 拍照批改）设计

日期：2026-11-01
状态：已确认，待实现
范围：把「生词/单词听写」从线上打字改为「线上听 + 线下手写 + 拍照上传 + 视觉模型自动批改 + 错词重写」

## 背景与目标

现有听写（`startDictation` → `submitDict`）是**线上打字**：孩子听语音，在输入框打字，系统比对 `s.input === w.w`。这违背了「听写」的本质——听写应该**手写**（锻炼字形记忆），而不是打字（打拼音就能出候选字，练不到字形）。

目标：改为「线上听 + 线下手写 + 拍照上传 + 自动批改」的完整闭环：
- 孩子听语音、用本子**手写**
- 写完**拍照上传**
- 系统用**视觉大模型自动批改**（识别手写字、判对错）
- **错词重写**（只重写错的）
- 错词**收录错题本**（统计错误次数）
- 批改结果**家长可复核、孩子可申诉**

## 需求参数（已确认）

| 项 | 值 |
|----|-----|
| 听写节奏 | 逐词听写（听一个写一个），可重听 |
| 提示 | 生词分两级：拼音 → 释义；单词提示中文意思 |
| 拍照粒度 | 全部听完写完整页 → 拍一张整页 |
| 批改方式 | 视觉大模型直接判对错（方案2：标准词列表 + 手写照片 → 每词对错） |
| 错词重写 | 只重写错的词，单独拍一张，只判错词 |
| 错词统计 | 收录错题本（Mistake），重复错累加 mistake_count |
| 复核/申诉 | 家长端看批改结果；孩子可申诉 |

## 第一部分：听写流程

### 状态机

```
listen（听写中）
  → 逐词：播放 TTS → 孩子手写 → 下一个词
  → 可「重听」「提示」（生词拼音→释义，单词中文）
  → 全部听完 → phase='upload'

upload（拍照上传）
  → 拍整页照片 → 上传 → phase='grading'

grading（批改中）
  → 视觉模型判对错 → phase='result'

result（结果展示）
  → 列出对错，错词显示正确答案
  → 有错词 → phase='rewrite'（只重写错词）
  → 全对 → phase='done'（完成打卡）

rewrite（错词重写）
  → 只对错词：重听、重写、拍一张（只有错词）、再判
  → 循环直到全对
```

### 提示机制

- **生词**：点一次「提示」→ 显示拼音；再点一次 → 显示释义
- **单词**：点「提示」→ 显示中文意思

## 第二部分：自动批改（视觉模型）

复用 `services/ai.py` 的视觉模型能力（`ocr_image` 用的是 vision_model，默认 qwen3-vl-plus）。

新增「手写批改」服务，指令改为「判对错」而非「识别文字」：

```python
def grade_handwriting(db, image_bytes, words: list[dict]) -> list[dict]:
    """用视觉模型比对标准词列表与手写照片，返回每词对错。

    words: [{index, word}]   # 标准词（含顺序）
    返回: [{index, word, is_correct, written}]  # written 是识别到的孩子写的内容
    """
```

prompt 要点：
- 传入标准词列表（含顺序）+ 手写照片
- 让模型按「从上到下」的顺序，识别每个手写词，和标准词比对
- 输出 JSON：`{"results":[{"index":0,"written":"孩子写的","is_correct":true/false}]}`
- 强调「形近字、潦草字要仔细辨认」，因为小学生手写可能不规范

## 第三部分：错词重写

批改后，错词列表保留。重写阶段：
- 只播放/显示「错词」的语音和提示
- 孩子只重写这几个错词
- 拍一张（只有错词）→ 再判这几个错词
- 循环直到全部写对

## 第四部分：错词统计 + 错题本

复用现有机制：`dictation_complete`（`learning.py`）已经把错词写进 `Mistake` 表（`source_type="dictation"`），`Mistake.mistake_count` 累加重复错误。

手写听写完成时：
- 错词写 `Mistake`（question="听写词语：X"，correct_answer=X，word_bank_id）
- 重复错的词 `mistake_count` 累加

## 第五部分：复核 + 申诉

### 家长复核

家长端「任务」tab 已有「查看照片」链接（`photo_path`）。手写听写的照片上传后，家长能在任务审核时查看手写照片，复核批改结果。

### 孩子申诉

批改结果页，每个被判「错」的词，孩子可以点「申诉」：
- 申诉 → 该词标记「待复核」→ 家长端看到申诉 → 家长人工判定对错 → 改判

## 数据流

```
听写词列表 → 逐词 TTS + 提示 → 孩子手写
  → 拍照上传（整页 image）
    → 视觉模型判对错（标准词列表 + image → [{word, is_correct, written}])
      → 展示结果（对错 + 正确答案）
        → 错词 → 重写（只错词）→ 再拍 → 再判
        → 全对 → 落掌握度 + 错题本 + 打卡
        → 申诉 → 家长复核 → 改判
```

## 接口

```
# 手写批改（新）
POST /api/dictation/grade-handwriting
  body: {user_id, words: [{index, word}], image: base64 或 multipart}
  → {results: [{index, word, is_correct, written}]}

# 申诉（新）
POST /api/dictation/appeal
  body: {user_id, word, word_id, reason}
  → 标记该词「待复核」

# 复用现有
POST /api/dictation/complete   → 完成打卡 + 错题本 + 掌握度
POST /api/tasks/{id}/upload-photo  → 照片上传
```

## 明确不做（本阶段）

- 不做「逐词拍照」（保持整页拍）
- 不做「手写笔迹评分」（只判对错，不评美观）
- 不做离线 OCR（用视觉模型在线判）
- 不做「拍照自动裁剪/矫正」（先假设照片是正常拍摄的整页）

## 技术风险

1. **手写识别准确率**：小学生手写（潦草、形近字、擦改）识别有误差。缓解：视觉大模型（qwen3-vl-plus）比传统 OCR 强；允许申诉 + 家长复核兜底。
2. **词序对齐**：孩子写乱序/歪斜时，模型「按序对齐」可能错位。缓解：prompt 强调「按从上到下顺序」，且允许申诉纠正。
