## 一句话

> 在现有「孩子写一段、家长看原话」之上，**可选**让 AI 只追问缺口；若用过追问，提交时生成一句家长侧「可能卡在…」。**仍不判定、不写掌握度。**

## 为何现在加 AI（以及仍不加什么）

最简版已证明：**「讲得好不好」不能自动判定**（见前置 spec 附录五轮失败）。  
本版只加两类**不依赖判定**的 AI 用途：

| 角色 | 做什么 | 不做什么 |
| --- | --- | --- |
| **A 追问者** | 针对孩子已写正文，每次只问 1 个缺口问题（≤3 轮） | 不讲解、不给定义、不补答案、不说对错 |
| **D 家长摘要** | 用追问痕迹生成一句「可能卡在…」 | 不说掌握/完整度/分数；未追问则不出摘要 |

**明确不做**：判定者、差分测试、用摘要写 mastery、并入 `/api/ask` chat（会讲解）。

## 一、孩子侧流程

1. 选题 → 写正文（与现网相同）。
2. 正文非空时出现「让 AI 问问我」。
3. 点开后不离页：AI 每次只返回 **1** 个问题；孩子作答后可继续；**最多 3 轮**。
4. 任意时刻可点「讲完了」提交；也可先改正文再交。
5. 从未点追问 → **零 AI 调用**，路径与现网一致。

硬规则（capability + 测试，不只靠文案）：

- 只追问；禁止讲解 / 给定义 / 填缺口 / 「对、错、讲得好」。
- 追问不得把答案关键概念词当作「提示」塞进问题里完成填空。
- 结束页仍仅「记下来了」类中性文案，无任何评价。

## 二、家长端与落库

家长端「孩子讲的」仍以 **`text` 终稿**为主。

仅当本次带有追问记录时，原文下增加一行灰色小字：

> 可能卡在：……

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `text` | 已有 | 终稿 |
| `probe_turns` | JSON 文本，可空 | `[{q, a}, …]`，审计与生成摘要用 |
| `parent_hint` | 短文本，可空 | 一句「可能卡在…」；未追问必须为空 |

规则：

- 摘要在 **POST /notes 提交时**生成一次并写入；家长打开只读，不实时再调模型。
- 摘要失败 → `parent_hint` 留空，**不影响** note 写入成功。
- 摘要模板化：只描述缺口线索；禁止评价词（好/对/掌握/完整等）。
- 未读红点逻辑不变（note id 水位）；与 hint 有无无关。
- 表结构**继续禁止** `verdict` / `score`；不新增判定语义字段。  
  （`probe_turns` / `parent_hint` 是交互痕迹与决策提示，不是判定结果。）

模型 docstring / 测试需同步：从「也不做 AI 交互」改为「不做判定；可选追问与家长提示不算判定」。

## 三、架构与接口

### 3.1 为何不挂 `/api/ask`

现有 `chat` / `visualize` / `solve` 会讲解或解题，与「只追问」冲突。本功能用独立 capability，避免串味。

### 3.2 无服务端会话表

最多 3 轮：由**客户端**每次请求携带 `text` + 已有 `turns[]`。  
不扩展 `UnifiedContext` 对话历史，不新建跨 turn 会话表。

### 3.3 Capability：`expression_probe`

- 工具：无（或仅只读解析题目标题；不写 mastery / 不写 note）。
- 输出：下一句追问纯文本；已满 3 轮则 `done: true` 且不再提问。
- system：只追问；禁讲解、禁对错、禁塞答案关键词。

### 3.4 端点（`/api/expression`）

| 方法 | 行为 |
| --- | --- |
| `POST /probe` | 入参：topic 标识（`knowledge_point_id` 或 `item_id`）、当前 `text`、`turns[]`。出参：`question`，或 `done: true`。年级 &lt;3 → 403。 |
| `POST /notes`（扩展） | 若 body 含非空 `probe_turns`，同步尝试生成 `parent_hint`；失败则 hint 空，note 仍 201。无 `probe_turns` 时 hint 必须为空且不调摘要模型。 |

年级门槛、孩子写/家长读权限与现有 expression 一致。

### 3.5 fake / 降级

- fake provider：`/probe` 返回固定问句模板；满轮返回 `done`。
- 摘要在 fake 或失败时：`parent_hint=""`（或固定无评价占位，默认倾向空，避免假装洞察）。

### 3.6 明确不写

不写 `WordMastery` / `KnowledgeMastery`；不把追问记为「学会了」；不做差分判定。

## 四、失败处理

| 情况 | 行为 |
| --- | --- |
| probe 超时 / 模型不可用 | 追问区提示「这会儿问不了」；正文与「讲完了」仍可用 |
| hint 生成失败 | note 成功；`parent_hint` 空 |
| 空正文请求 probe | 前端禁用；服务端 400 |
| 第 4 轮及以后 | `done: true`，不再提问 |

---

## 五、验收

- 未点追问：与现网一致；提交路径不因本功能多调 AI（无 `probe_turns` 时摘要也不调）。
- 追问 ≤3 轮；超额请求返回 `done`。
- 有 `probe_turns` 才可能有 `parent_hint`；无追问则 hint 必空。
- 表无 `verdict` / `score`；既有「禁止判定列」测试保留并扩展字段白名单说明。
- 年级 &lt;3：`/probe` 与 `/notes` 均 403。
- 结束页 / 家长摘要文案不含评价词（测试可用禁用词表）。

**产品成功标准**：家长能凭「原文 + 可选一句卡点」决定要不要聊；系统**不宣称**孩子讲懂了。

---

## 六、范围外（本版不做）

- 语音转文字 / 多通道输入  
- 强制改终稿  
- 家长端展开完整追问对话（可后续；本版只存 `probe_turns` 备审计）  
- 用 `parent_hint` 或追问轮次写掌握度  
- 并入 chat capability / 完整「教 AI 直到掌握」状态机

## 八、9 问自检（学习第一性原理）

1. **类**：探究型表达练习（习惯/动机从属）；不做识记自动化宣称。  
2. **关系**：孩子能否用自己的话组织该知识点的关系（压缩/表述）。  
3. **变换**：生成（讲出教材未逐字给出的表述）；追问只引发，不代做。  
4. **通过证据**：本版**不设系统通过**；家长人工看。  
5. **谁先产出**：孩子先写正文；AI 可选后追问。  
6. **通道**：本版仍以文字为主（年级 ≥3）。  
7. **年龄**：沿用 ≥3；低年级不做反事实式追问。  
8. **测不准**：不判通过/不通过；摘要失败记空，不硬判。  
9. **愿学 vs 学会**：影响「愿不愿讲清楚」与家长决策；**不**参与「学会了没」。
