## 1. 背景与目标

「知学伴」是一个面向**小学生**（由家长管理）的 AI 学习辅助智能体，核心是搭建一条「学习 → 检测 → 获得积分 → 兑换娱乐时间」的正向闭环，激励孩子持续完成每日学习任务。

### 核心原则

- **游戏化激励**：通过积分把"学习"和"娱乐时间"挂钩，让孩子有内在动力。
- **AI 作为教学助手**：AI 负责出题、批改、陪伴对话，家长负责设定目标与规则。
- **家长可控**：家长端能设定教学目标、查看进度、管理积分兑换规则。
- **原型优先**：先做出可运行的原型验证核心闭环，再逐步完善。

## 2. 目标用户与角色

| 角色 | 描述 | 核心诉求 |
|------|------|----------|
| 孩子（小学生） | 主要使用者，在平板/手机上完成每日打卡 | 有趣、有成就感、能兑换娱乐时间 |
| 家长 | 管理者，设置目标与规则、监督进度 | 省心、可控、看到学习效果 |

## 3. 功能范围

### 出题机制总览

所有题目的**知识内容以家长录入的教材内容为准**（生词表、单词表、课文文本、知识点），AI 不凭空编造内容，只负责：

1. **组题**：根据进度/遗忘曲线/薄弱加权从内容中选取词语、知识点，生成题目形式
2. **批改**：判断孩子答案对错
3. **对话**：陪伴式讲解与鼓励

### 3.0 教材录入与拆课（家长端）

家长上传 PDF 教材，系统自动拆分成一课一课，作为后续出题/听写/阅读的内容来源。

**核心思路：PDF 建索引，保留原页图片与排版**

- **保留原貌**：PDF 原文件每一页（含图片、排版）原样保留，孩子"个性化学习"阅读区直接展示原版页面，不丢失插图与格式。
- **建立索引**：拆课只建立"第 N 课 = 第 X~Y 页"的映射，不把 PDF 转成纯文本替换原文。
- **结构化提取**：生词表、单词表、知识点这些机器可读数据，由大模型（DeepSeek/GLM）从对应页**自动提取**，存库供出题/听写/批改使用，并关联到具体页码。

**拆课流程**：

```
家长上传 PDF 教材（指定学科）
→ 系统按学科规则解析 PDF，识别切分锚点（第X课/UnitX/第X单元），切分页码范围
→ 大模型按学科配置对每课自动提取结构化内容（关联页码）
→ 家长在页面逐课查看提取结果，审核（可修正）后入库
→ 生成教材目录（textbooks），供进度驱动、听写、出题使用
```

- **审核机制**：大模型自动提取的结果**必须经家长审核后才正式入库**。未审核的课处于"待审核"状态，**不进词库、不出题、不参与听写/进度**；只有审核通过（可修正后再通过）才激活。审核是拆课流程的正式关卡，而非可跳过的预览。
- **拆课粒度**：一课 = 页面索引（第 X~Y 页，映射到 `pdf_pages` 原版页面）+ 结构化内容（`texts` 课文文本 + `word_banks` 生词/单词表 + `knowledge_points` 知识点），三者通过 `lesson_id` 关联。孩子阅读展示原版 `pdf_pages` 页面，出题/听写/批改使用结构化内容。

**学科拆课规则（共用骨架 + 学科配置）**

拆课动作本身（解析 PDF → 识别锚点 → 切页 → 大模型提取 → 审核）是**同一套通用骨架**，但「切分锚点」和「提取的结构化内容」因学科而异，作为**学科配置**（而非写死一套规则）驱动：

| 学科 | 切分锚点 | 提取的结构化内容 |
|------|----------|------------------|
| 语文 | 「第 X 课」课文标题 | 生词表（词 + 拼音 + 释义）+ 知识点（拼音/字词/句式/古诗文） |
| 英语 | 「Unit X / Lesson X」单元 | 单词表（词 + 音标 + 词性 + 释义）+ 句型/语法点 |
| 数学 | 「第 X 单元 / 例题 / 练习」 | 知识点（概念 + 公式 + 例题），**通常无生词/单词表** |

- **语文/英语**：以"课文/单元"为载体，结构化核心是生词/单词表 + 知识点。
- **数学**：以"单元 + 例题"为载体，结构化核心是知识点（概念/公式/例题），`word_banks` 对应字段为空或改作"术语表"，不强行套"生词表"。
- 新增学科只需在配置里声明「锚点 + 字段模板 + 提取 prompt」，骨架与审核流程不变。

### 3.1 听写打卡（语文生词 + 英语单词）

**出题逻辑：进度驱动 + 遗忘曲线复习 + 薄弱加权**

- **进度驱动（当天新课）**：产品预置教材目录（课文/生词表顺序）。进度**以孩子触发推进为主、家长修改为辅**——孩子主动"进入下一课"时，需先**阅读该课原版教材内容（`pdf_pages` 原页展示）+ 回答理解题**，正确率达到阈值（默认 60%）才判定该课完成、进度推进到下一课；阅读/答题中不懂可随时向 AI 提问（见 3.1.1）；家长端保留手动调整能力，用于孩子卡住或误操作时纠正。当天听写以当前进度的**全部生词/单词**为主。
- **遗忘曲线复习（旧词）**：之前学过的生词/单词，按遗忘曲线（艾宾浩斯）安排复习，在即将遗忘的时间点重新出现。
- **薄弱加权**：错词（薄弱环节）的复习频率适当调高——错过的词在后续听写中更频繁出现，直到稳定掌握。
- **无新课日**：如果当天没有学新课程，则听写内容完全由"遗忘曲线 + 薄弱环节"决定，复习相应单词和生词。

**听写出题方式**：从词库中按上述逻辑选出 N 个词，TTS 逐个朗读（可设置重复次数、间隔），孩子输入/选择拼写。

**打卡流程**：TTS 朗读词语 → 孩子输入拼写 → AI 自动批改 → 正确得分，错误进入错题本 → 完成听写即打卡，获得积分。

### 3.1.1 学习中的「不懂就问」（沉浸式学习）

孩子**阅读原版教材 + 答题**的整个过程中，遇到不懂的地方可随时请教 AI。参考 DeepTutor「沉浸式阅读」：**左侧/上方展示原版教材页面（`pdf_pages` 原页，保留课本图片与排版），右侧/下方是 AI 对话区**，孩子可就当前看到的课文内容划词、选段或直接输入提问，AI 结合教材上下文讲解。

**按学科的讲解形态**：

| 学科 | 讲解形态 | 说明 |
|------|----------|------|
| 数学 | 思维导图 / manim 动画 / SVG / 交互式 HTML | 概念、公式、例题用可视化方式讲解（几何图形、动画演示、可拖拽的交互控件） |
| 语文 | AI 对话答疑 | 字词释义、句式、古诗文背景等，通过对话逐步讲透 |
| 英语 | AI 对话答疑 | 单词用法、语法、句型等，通过对话讲解，可配合 TTS 示范读音 |

- **统一入口**：孩子在看教材、答题的任意环节都能发起提问；提问上下文（当前页码、正在做的题、选中的文字）自动带入 AI，无需孩子复述。
- **讲解形态由学科 + 知识点类型决定**：数学知识点命中「可视化可讲解」时优先用思维导图/动画/SVG/交互式 HTML，其余用 AI 对话；语文、英语一律 AI 对话（必要时叠加 TTS 示范发音）。
- **降级**：可视化生成失败时降级为纯 AI 对话讲解，保证"不懂就问"始终可用。
- **不打断主线**：提问是辅助，不影响"阅读 + 答题达标"的进度推进判定；答疑内容不计入考核，但可帮助孩子通过考核。

### 3.1.2 学习笔记

孩子在**阅读教材、答题、向 AI 提问**的整个学习过程中，可随手记笔记。笔记是孩子的学习沉淀，贯穿整个学习闭环。

**两种笔记形态（两者都要）**：

1. **划词/选区锚定笔记**：在教材页面上选中一段文字，弹出「记笔记」，笔记**锚定到这段原文**（记录选中文字 + 所在页码）。复习时能回到原文语境看到笔记。
2. **按课汇总的笔记本**：每课有一个「我的笔记」面板，收录该课所有笔记（含锚定的划词笔记 + 自由笔记），按时间排列，可翻阅、编辑、删除。

**笔记的关键特性**：

- **家长可见**：笔记在家长端可查看（了解孩子哪里记了、记了什么），符合"家长可控"定位，但不修改孩子的笔记内容。
- **轻量 AI 联动（可选）**：可让 AI 把某条笔记或整课笔记「整理成知识点」「生成复习卡 / 速记卡」，纳入后续复习与出题；默认关闭，家长可开启。
- **关联学习闭环**：笔记可关联到知识点（`knowledge_points`），薄弱环节复盘时一并呈现，帮助定位孩子理解困难处。

**数据落点**：新增 `notes` 表（内容、锚定文字、页码、所属 `lesson_id`、作者角色、关联知识点、时间）。

### 3.2 基础知识复习（语文 + 英语）

**「基础知识」的范围定义**（区别于 3.1 的生词/单词听写：听写考的是"词怎么写"，基础知识考的是"词/句/语法怎么用、背后的规则"）：

**语文基础知识（类别清单）**

| 类别 | 说明 | 示例 |
|------|------|------|
| 拼音 | 声母/韵母/声调、拼音拼写规则 | "徘徊"的拼音、多音字读音 |
| 字词 | 形近字、多音字、近反义词、词语搭配 | "矗立 vs 耸立"辨析 |
| 句式 | 句式转换、修辞、标点 | 把字句/被字句、比喻拟人 |
| 古诗文 | 名句默写、作者朝代、释义 | "不识庐山真面目"作者 |

**英语基础知识（类别清单）**

| 类别 | 说明 | 示例 |
|------|------|------|
| 语法 | 时态、词性、单复数、第三人称单数 | 动词三单加 s |
| 句型 | 固定句型、疑问句/否定句结构 | There be 句型 |
| 词汇用法 | 词义辨析、固定搭配、介词搭配 | look at / look for 区分 |

- 每类知识点以 `knowledge_points` 表存储，带 `subject`（语文/英语）+ `category`（上表类别）字段，供分组出题与家长端薄弱报告按类别汇总。
- 同样遵循**进度驱动 + 遗忘曲线 + 薄弱加权**的出题逻辑
- 复习形式：选择题、填空题、判断正误等

**出题方式**：家长录入/审核通过的知识点（如"动词第三人称单数加 s"），AI 据此生成对应题型——例如判断正误"go → gos 对不对？"、填空"He ___ (go) to school."、选择"下列哪个动词三单形式正确"。薄弱知识点出题频率更高。

- 答错的题自动加入**错题本**（见 3.7）
- 完成复习任务获得积分

### 3.3 专项练习（英语听力 + 语文阅读理解）

- **英语听力**：基于当前进度的单词/句型，AI 生成听力材料（对话/短文），TTS 播放，出理解题（选择/填空）
- **语文阅读理解**：基于当前进度的课文或适配年级的短文，AI 生成理解题
- 答错的题自动加入**错题本**（见 3.7）
- 完成练习获得积分

**出题方式**：
- **听力**：AI 把已学单词/句型组织成一段对话或短文（内容仍基于已学词汇），TTS 朗读，孩子听后回答理解题（如"对话里提到了哪个单词"、"小明要去哪里"）。
- **阅读理解**：优先选用家长录入的课文文本，AI 出理解题；课文不足时 AI 生成与当前进度词汇量匹配的短文再出题。

### 3.4 积分奖励

- 完成任务获得积分，积分可累计
- 积分记录可查看（孩子端 + 家长端）

### 3.5 教学目标出题考核

- 家长设定教学目标（如"掌握第 3 单元所有生词"）
- AI 根据目标出题考核，判断孩子是否掌握
- 考核通过则标记目标达成，可兑换奖励
- 答错的题自动加入**错题本**（见 3.7）

**目标拆解为知识点地图（参考 DeepTutor"精通之路"）**：

- 家长用一句话说出目标（如"掌握三年级上册第 3 单元"），AI 与家长在对话中把目标拆解成**知识点清单/地图**
- 每个知识点独立记录掌握程度（未学 / 学习中 / 已掌握）
- 每个知识点按各自的遗忘曲线节奏到期复习
- 知识点全部达到"已掌握"，目标即判定达成

### 3.6 积分兑换设备使用时间

- 积分兑换"平板/手机使用时间"
- 结合系统家长控制实现真实锁定（iOS 屏幕使用时间 / Android Family Link）
- 产品作为计时器与引导工具，配合系统能力

### 3.7 错题本（贯穿所有练习类型）

- **适用范围**：听写、基础知识复习、听力、阅读理解、目标考核中所有**答错的题/词**统一收录
- 错题本中的内容纳入"薄弱加权"逻辑，提高后续复习频率
- 错题被连续答对若干次后，从错题本移除（标记为已掌握）

### 3.8 错误频率统计

对错误进行**两级频率统计**，用于定位薄弱环节：

- **词/题级**：统计每个词或每道题的错误次数、错误率、连续答对次数（如"某个生词错了 3 次"）
- **知识点/类型级**：按知识点或题型汇总（如"拼音类错 15 次、句型类错 8 次"），识别哪类知识整体薄弱
- **作用**：① 作为薄弱加权的数据依据，高频错点复习频率更高；② 在家长端展示薄弱环节报告，帮助家长了解孩子学习状况

## 4. 技术架构

### 4.1 技术栈

| 层 | 技术 | 说明 |
|----|------|------|
| 后端 | Python + FastAPI | 业务逻辑、API、AI 调用、定时任务 |
| 数据库 | MySQL（生产）/ SQLite（开发） | 存用户/题库/积分/学习记录；开发用 SQLite 零部署，生产用 MySQL，由 ORM + 连接串切换 |
| AI | 国产大模型（OpenAI 兼容协议） | DeepSeek / GLM(智谱) 等，出题、批改、陪伴对话 |
| 语音 | 第三方 TTS（可插拔） | MiniMax / 科大讯飞等，接口抽象可替换 |
| 前端 | HTML + JS（响应式） | 孩子端 + 家长端两套界面 |

### 4.3 模块划分

每个模块职责单一、接口清晰，可独立理解和测试：

1. **认证模块**：家长/孩子登录与角色区分（原型阶段可简化）
2. **题库/词库模块**：教材词库 + 家长自定义词库的存储与查询
3. **学习模块**：听写、复习、听力、阅读理解四种任务类型的流程编排
4. **AI 服务模块**：多厂商大模型接入（出题、批改、对话）
5. **TTS 适配模块**：语音朗读的统一接口，支持 MiniMax / 科大讯飞等多厂商切换
6. **积分/兑换模块**：积分累计、兑换记录、与系统家长控制的对接
7. **目标/考核模块**：教学目标管理、AI 出题考核、掌握度判断

### 4.4 AI 服务层设计（多厂商）

由于 DeepSeek、GLM（智谱）等国产模型都提供 **OpenAI 兼容接口**，AI 服务层采用「统一抽象 + 多厂商适配」的方式：

- **统一接口**：`AIProvider` 抽象基类，定义 `generate(prompt, system, json_mode)`、`stream(...)` 等标准方法，上层（出题/批改/对话）只依赖这个接口，不感知具体厂商。
- **厂商适配器**：`DeepSeekProvider`、`GLMProvider` 等，各自实现上述接口。DeepSeek 用 `https://api.deepseek.com`（`deepseek-chat`/`deepseek-reasoner`），GLM 用 `https://open.bigmodel.cn/api/paas/v4`（`glm-4-plus`/`glm-4-flash`）。
- **配置切换**：家长在**页面（家长端设置页）**配置 AI 默认厂商/模型 + API Key、TTS 默认厂商/音色 + API Key，配置持久化到 `model_config` 表；`provider = get_provider()` 按配置返回对应适配器实例，切换模型零改动业务代码、无需改环境变量。
- **降级策略**：某厂商调用失败（超时/限流/网络异常）时，可配置自动降级到另一厂商；同时保留本地题库兜底，保证核心功能（听写、复习）在 AI 不可用时仍可用。
- **结构化输出**：出题/批改需要返回固定 JSON（题目列表、对错判断），统一要求 `json_mode`，各适配器用各自支持的 JSON 输出能力实现。

> 说明：初期以 **DeepSeek** 为主力（便宜、中文出题/批改强），**GLM** 作为备选可切换；两者都通过 OpenAI 兼容协议接入，新增其他厂商只需再写一个适配器。

### 4.5 TTS 语音模块设计（多厂商，可插拔）

听写打卡、英语听力等场景依赖语音合成（TTS），同样采用「统一抽象 + 多厂商适配」，初期支持 **MiniMax** 和 **科大讯飞**：

- **统一接口**：`TTSProvider` 抽象基类，定义 `synthesize(text, voice, speed) -> audio_bytes`（或返回音频 URL），上层只调用这个接口，不感知厂商。
- **厂商适配器**：
  - `MiniMaxTTS`：MiniMax 语音合成（`https://api.minimax.chat`），支持多种音色、语速调节，中文发音自然，适合生词/单词听写朗读。
  - `XunfeiTTS`：科大讯飞开放平台语音合成（WebAPI / 流式），中文发音权威、稳定，适合语文生词听写。
- **配置切换**：与 AI 服务层一致，家长在**页面**配置启用的 TTS 厂商、音色、语速、重复次数、朗读间隔，持久化到 `model_config` 表。
- **降级策略**：某厂商失败时降级到另一厂商，最终兜底到浏览器原生 `speechSynthesis`（本地免费，原型阶段即用它）。
- **听写衔接**：听写流程中，TTS 朗读词语 → 孩子输入，重复次数/间隔由配置控制；英语听力场景则用 TTS 合成整段对话/短文后播放。

> 说明：TTS 为付费第三方服务，实现时接口抽象好，后续可无缝替换（如换成阿里云、火山引擎等）。

## 5. 数据模型（核心表）

> **数据库双轨**：生产用 **MySQL**，开发用 **SQLite**。通过 ORM（如 SQLAlchemy）+ 连接串切换，业务代码不写死方言；表结构与迁移脚本保持两库一致，避免 SQLite 能跑、MySQL 跑不通（或反之）。开发阶段零部署用 SQLite 快速迭代，上线切换连接串即可。

- **users**：用户（家长/孩子），含角色
- **pdf_documents**：上传的 PDF 教材（文件名、学科、存储路径、原文件）
- **pdf_pages**：PDF 每一页的**原始页面图像/引用**（所属 `pdf_documents`、页码、页面图像路径）。拆课时把每一页渲染为图片（或保留原 PDF 内嵌页面引用），**原样保留图片与排版**，供孩子"个性化学习"阅读区按页展示原版页面。
- **lessons**：拆课后的一课（所属教材 `pdf_documents`、学科、课文标题、起始页码、结束页码、提取状态、**审核状态**）。拆课只建「第 N 课 = 第 X~Y 页」的映射，**不转纯文本替换原文**；一课通过 `lesson_id` 关联下方 `texts` / `word_banks` / `knowledge_points` 三类结构化内容。审核状态（待审核 / 已通过 / 已驳回）决定该课是否激活：**未通过审核的课不进词库、不出题、不参与进度**。
- **textbooks**：教材目录（学科、单元、课文、生词/单词表顺序）
- **learning_progress**：学习进度（当前学到第几课，家长点选或手动调整）
- **word_banks**：词库（教材来源 / 家长自定义），每个词关联所属 `lesson_id`（一课）
- **knowledge_points**：基础知识库（语文：拼音/字词/句式/古诗文；英语：语法/句型/词汇用法；带 `subject` + `category` 字段供分组出题与薄弱报告按类别汇总，关联所属 `lesson_id`）
- **texts**：课文的结构化文本（由大模型从原页提取，供 AI 出题/批改/阅读理解使用，关联所属 `lesson_id`）。**注意区分**：阅读展示一律走 `pdf_pages` 原版页面图，`texts` 只作为机器可读的文本副本，不用于重新排版展示。
- **notes**：学习笔记（内容、锚定文字、页码、所属 `lesson_id`、作者角色、可选关联 `knowledge_points`、时间）。划词锚定笔记 + 按课汇总笔记本共用此表。
- **word_mastery**：每个词的掌握状态（学习日期、正确/错误次数、薄弱标记、下次复习时间）
- **mistakes**：错题本（统一收录各类型答错的题/词，含来源类型、错误次数、连续答对次数）
- **learning_records**：学习记录（听写/复习/练习，含对错、日期）
- **points**：积分流水（获得/消费）
- **goals**：教学目标（内容、状态、达成时间）
- **rewards**：兑换记录（积分 → 使用时间）
- **model_config**：模型配置（家长在页面设置：AI 默认厂商/模型 + API Key、TTS 默认厂商/音色 + API Key，存库持久化）

> **索引与内容的职责分层**：`pdf_documents`（原文件）→ `pdf_pages`（原页图像，保排版）→ `lessons`（页码索引，纯映射）→ `texts`/`word_banks`/`knowledge_points`（结构化内容，供出题/听写/批改）。「孩子看什么」由 `pdf_pages` 决定，「机器算什么」由结构化表决定，两者通过 `lesson_id` 关联。

> 遗忘曲线与薄弱加权的核心是 `word_mastery` 表：记录每个词的掌握状态，据此计算"下次复习时间"（遗忘曲线）和"复习频率加权"（薄弱环节）。

## 6. 关键流程

### 6.1 进度推进流程（孩子触发为主）

```
孩子主动"进入下一课"
→ 系统展示该课教材内容（课文/生词表，孩子阅读）
→ AI 根据该课内容出理解题 → 孩子答题
→ AI 批改，计算正确率
→ 正确率 ≥ 阈值（默认 60%）？ 
   ├─ 是：该课标记完成，进度推进到下一课，获得积分
   └─ 否：提示重看内容后重答（错题入错题本）
→ 家长端可手动调整进度（辅助，用于孩子卡住/误操作）
```

> 进度推进由孩子学习行为驱动，家长修改仅作兜底。达标阈值可在家长端配置。

### 6.2 听写打卡流程

```
系统确定当天听写范围（基于当前进度）：
   ① 当天新课的全部生词/单词（进度驱动）
   ② 到达遗忘曲线复习点的旧词（遗忘曲线）
   ③ 错词/薄弱词（薄弱加权，频率调高）
→ AI 出词 + TTS 朗读 → 孩子输入拼写
→ AI 批改 → 更新 word_mastery（正确/错误、下次复习时间）
→ 错误入错词本 → 完成打卡 → 发放积分
```

> **无新课日**：若当天无新课程，听写范围完全由"遗忘曲线复习点 + 薄弱错词"决定。

### 6.3 教学目标考核流程

```
家长设定目标（如"掌握第3单元生词"）
→ AI 生成考核题 → 孩子答题
→ AI 判断掌握度 → 达成/未达成
→ 达成后目标标记完成，可触发奖励
```

### 6.4 积分兑换流程

```
孩子积累积分 → 在兑换页用积分兑换"使用时间"
→ 系统记录兑换 → 引导家长在系统家长控制中设置对应限额
→ 产品提供计时/倒计时工具辅助
```

## 7. 错误处理与边界

- **AI 调用失败**：出题/批改失败时降级到本地题库，保证核心功能可用
- **TTS 失败**：回退到浏览器自带语音，或文字提示
- **兑换锁定边界**：明确产品不直接锁设备（受系统限制），定位为"系统家长控制的引导与计时伴侣"

## 8. 范围边界（YAGNI）

原型阶段**暂不做**：

- 复杂的多用户/学校班级系统
- 数据统计报表（仅保留基础进度查看）
- 消息推送/通知系统
- 移动端原生 App 打包
- 付费订阅/商城

## 9. 成功标准

1. 孩子能完成一次完整的"听写打卡 → 获得积分"闭环
2. 家长能设定一个教学目标，并看到 AI 出题考核结果
3. 积分能兑换"使用时间"，并有对应的系统家长控制引导
4. 四种学习任务（听写/复习/听力/阅读）都能跑通
